## 设计要点（决定实现顺序）

1. **加法优先，最小化触碰字幕路径**：新建 `capability.ts` + `compose-input.ts`，复用 kind 无关的 `ledger.upsert/advance` 与 `rework_requests` 表；`baseline.ts`/`apply.ts`/`contract.ts` 本切片**不改行为**（Rule 0.5 范围纪律）。指纹核与门禁在 capability.ts 内以"同语义独立实现"落地，避免为复用而回归风险；如后续要收敛为单一 helper，另立独立提交并过全量门槛。
2. **台账判别**：ledger 行 `previewJson`/`resultJson` 内带 `reworkType: 'subtitle' | 'compose-input'`；compose-input 走**专属 preview/apply 端点与服务函数**，不重载字幕 `buildSubtitlePreview`/`applySubtitleRework`，字幕 apply 端点与语义逐字不变。
3. **成本诚实**：preview/apply 回执固定 `localReencode:true, modelCalls:0, charged:false`；无字幕"关烧录逐字节复制"快速路径——配置/换绑/选片改动经确认必触发真实 FFmpeg 重编码（复用 `resetStepForRecompose` 语义）。
4. **入口收口（对齐"同类入口一次收口"强约束）**：所有本地重合成入口执行前统一调 compose-input 消费期指纹复验，任一绕过即 fail closed。

## 任务拆解（依赖顺序，每项 ≤~5 文件，先写失败探针再实现）

### T1 · 能力门禁与基准指纹核（纯新增）
- 文件：`services/rework/capability.ts`（新）；探针分节 `compose-input`。
- 内容：`assessComposeInputCapability(runId, stepKey)` — run 非在途/未取消 + 存在 `ffmpeg_merge` 且 succeeded + 无范围外 failed + 下游仅 LOCAL_SAFE/无待执行付费/无受理不确定 + 成片可固定；**不要求字幕快照**。`buildComposeInputFingerprint` = timelineCore + `readComposeConfig` + 当前 BGM 资产 id/sha + 各镜 SFX map + 各镜在用 assetId(`selectedMapOf`) + brand + `stepOutputs`/`assetHashes`。`computeFingerprintForComposeInputRecheck(runId, stepKey)` 消费期复验。
- 验收：门禁各失败态返回明确 code/blocked；指纹对 bgm_volume/bgm 资产/选片/brand 任一变即不同；无字幕成片仍可得基准（证不依赖快照）。
- Verify：`--only=precision-rework --section=compose-input`（T1 子断言）+ typecheck。

### T2 · 变更契约与校验（纯函数）
- 文件：`services/rework/compose-input.ts`（新，契约段）。
- 内容：`ComposeInputChange` zod 判别联合（compose-config/bgm/sfx/shot-select，schema §3）；`parseComposeInputChanges`/`normalize`/`diffComposeInputChanges`。配置规范化**复用** `compose-config.ts` 枚举/clamp 真源（不重抄，导出其纯函数或调用其 norm）；bgm/sfx 校 assetId 存在+kind=audio+属本项目+未删；shot-select 校目标资产同 kind 且在同一生成步骤 output 集合内；`no_effect` 整体拒。
- 验收：越枚举/越权资产/跨 kind 选片/无效 assetId/零变更全拒且不产出部分结果。
- Verify：探针契约分节断言 + typecheck。

### T3 · 预览编译器（零执行）
- 文件：`compose-input.ts`（preview 段）；`routes/rework.ts`（新 `POST /runs/:id/rework/compose-input/preview`）。
- 内容：`buildComposeInputPreview(runId, stepKey, requestKey, changes, sessionId?)` → T1 基准 + T2 校验/规范化/diff → 固定 `previewHash` + impact（resetSteps=[compose]、keepNotes 保留未受影响媒体清单、cost localReencode:true）→ ledger `ready`/`blocked` 回执（`reworkType:'compose-input'`）。同键同内容回放、异内容 conflict。
- 验收：预览不写 run/step/asset（只写台账）；预览返回逐处 原值→新值；无效 changes 登记 blocked 可经 requestId 回放原因。
- Verify：探针 preview 分节（零执行态写入断言）+ HTTP 用例。

### T4 · 原子确认与本地续跑
- 文件：`compose-input.ts`（apply 段）；`routes/rework.ts`（新 `POST /runs/:id/rework/compose-input/:requestId/apply`，只接 previewHash）。
- 内容：`applyComposeInputRework` — 重验 ready/previewHash/归属/依赖指纹一致；事务内把变更落到既有真源（配置→`run.input._compose` 经 updateComposeConfig 规范化；bgm/sfx→`bindBgmFromAsset`/`removeBgm`/`bindSfxFromAsset`/`removeSfx`；shot-select→`rebuildShotOutput`/在用映射，不覆写源、不删历史）+ 条件领用 run(completed/failed→queued) 与 compose step(succeeded→pending) + 作废旧 gate + 写 applied 回执；提交后 `engine.startRun`。幂等：同 requestKey 重放回执不二次入队；并发竞争只一方落锤。
- 验收：确认后仅 compose 步重置、gen_task 零增删改、usage 零增、旧 gate 作废、applied 回执可回放；stale 预览 409；未确认不改任何状态。
- Verify：探针 apply 分节 + 事务竞争/重放/过期断言。

### T5 · 全同类入口收口（消费期复验）
- 文件：`shot/reset.ts`（`resetStepForRecompose` 前置复验钩子）、`creation-chat/candidates.ts`（`recomposeCreation` 消费前）、`routes/runs.ts`（通用 recompose / resume）。
- 内容：这些入口在重置/入队前调 `computeFingerprintForComposeInputRecheck` 同族复验；存在已确认待生效的 compose-input 返修时按其固定输入本地重合成，基准漂移则 fail closed 并回明确原因。**保留各入口既有权限/计费语义**，仅追加"不使用过期合成输入基准"这一不变量。
- 验收：预览→旁路直改 `_compose`→经各入口重合成均被识别过期；字幕返修入口不受影响。
- Verify：探针 stale 分节逐入口断言 + 全量回归（字幕 277 断言不变）。
