## 一、北极星：统一决策权模型（三层）

痛点根因：平台把「决策」与「核实」两件事混在一起全推给了用户。建立贯穿全平台的分级模型，所有配置入口按此归类：

- **Tier A 自动推导**：系统有可信真源（适配器能力声明 / 定价表 / 上游文档 / 历史 run）→ 直接预填完整值，用户可改，不打断、无需勾选「已核实」。
- **Tier B 智能建议**：LLM/启发式，无绝对真源 → 给推荐 + 一键采纳，保留「预览再执行」闸门（复用 `canvasAdvice` 的「仅建议不执行」范式）。
- **Tier C 必须人工**：不可逆成本 / 密钥 / 法务合规 → 强制确认，不自动化。

一句话原则：**能推导的不问（A），需判断的建议（B），会花钱/不可逆的必须确认（C）。** 当前大量本属 A 的项被错误地放进了「用户手填」，是主要痛点来源。

关键安全约束：Tier A 不是「取消校验」，而是把「核实」的主体从**用户**转移到**系统真源表 + 执行前预览闸门**——即「系统负责核实、用户负责预览确认」，现有「不猜测 / 不静默降级 / 成本可见」安全线不降。

## 二、全平台配置面审计（6 类入口）

### 1. AI 配置（`/settings`）—— 痛点最高

- 现状：4 通道（llm/image/video/audio）逐个建实例、填 model、勾默认、配 `pricing`、写 `creationCapabilities`、语音 `emotion_map`。
- 强制手动但本可自动：
  - `creationCapabilities` 的时长/分辨率/模式档位系统已知三遍——前端 `applyCapsPreset`（`ApiConfigForm.vue` L163-193）、服务端 `assertAdapterDurations`（`services/creation-chat/preflight.ts` L44-53）、前端 `capsHint`（L57-75），却要用户逐项勾选 + 勾「已核实」。
  - 定价已有四级回退 `resolveUnitPrice`（`services/usage.ts` L100-134），但新实例仍需手填 `pricing`，未命中表时不自动带出。
  - 选模型后 model 名要手动复制进能力声明（现靠 watch 兜底，仍易错）。
- 目标形态：选供应商 + 粘 Key → 自动拉模型列表（已有 `POST /api-configs/fetch-models`）→ 选中即按 Tier A 生成完整实例（能力声明 + 定价 + 默认通道建议），用户只在异常时改；去掉「已核实」勾选，改由「适配器档位表背书」。

### 2. 模板 / 流水线（15+ YAML）

- 现状：`docs/getting-started.md` 明确「不再默认替你选模板」，用户选场景卡 → 逐项填 `inputs`。
- 可自动化：`TemplateInputDef.default` 与级联默认已存在（`pipeline/types.ts` L14-15 / L64-65），但多数 input 未配 default、不参考项目 brief 与历史 run。
- 目标形态：自然语言目标 → Tier B 推荐模板（复用 scene + LLM）；`inputs` 按「项目 brief + 上次同模板 run 入参」自动预填（Tier A），必填缺失才提示。

### 3. 项目设置（体裁 / brief / `settings.video`）

- 现状：建项目填体裁、简介；`settings.video` 参数级联。
- 可自动化：体裁→默认模板已预选；video 参数应改为从所选视频实例的能力档位自动取合法默认（Tier A），而非让用户填可能越界的值。

### 4. 运行参数（`RunParamsPanel.vue`）

- 现状：已做「只显示本 run 实际读取的参数组」的好减法。
- 可自动化：provider/model/resolution/duration 覆盖项给 Tier B 智能默认（按成本/质量推荐），而非空白手填。

### 5. 创作流程（轻松创作 / 画布 / 实体 / 风格 / 克隆音色）

- 现状：轻松创作要选模式、画幅、时长；实体制定妆、风格预设、音色均需手配。
- 可自动化：模式/画幅/时长由能力表 + 项目体裁推导（Tier A）+ 预检预览（已有 `preflightPlan`）；`canvasAdvice`（`services/creation/advice.ts`，M23）已具雏形，扩展为默认给下一步建议（Tier B）。

### 6. 运营配置（排期 / 合规词 / 平台适配 / 发布）

- 现状：合规词库 `workspace/compliance/words.txt`、平台预设、排期日历均需手动维护。
- 可自动化：平台预设按目标平台自动带出（Tier A）；合规词库提供内置基础词 + Tier B 按内容自动补充建议；排期按发布节奏模板自动建议。

## 三、统一基建（一次造，全站复用）

1. **能力/默认单一真源表**：把散落在适配器、前端 preset、服务端 assert 三处的「模型档位」收敛为一份 `provider-models` 注册表（适配器层声明 `durations/resolutions/modes/aspectRatios` + 默认定价），前端与预检均从此读，消除三处重复与「提示说支持、预检却拒绝」的自相矛盾。
2. **智能默认引擎（Tier A）**：输入「供应商+模型 / 体裁 / 项目」，输出预填值（能力声明、video 参数、定价、模板入参）。
3. **建议层（Tier B）**：把 `canvasAdvice` 的「确定性摘要 + LLM + 仅建议不执行」抽象为通用 recommend 服务，供模板选择、参数推荐、下一步建议复用。
4. **预览-确认闸门（复用）**：`preflightPlan` + 模板 `gate` 已是执行前预览的落地，统一作为 Tier A/B 自动值的最终人工确认点。
5. **可覆盖层（复用）**：现有 `run > project > template` 级联保持不变，作为「用户可覆盖」的机制底座。

## 五、各里程碑范围摘要

- **M32 能力/默认单一真源表 + 智能默认引擎（基建）**：收敛三处档位重复；`creationCapabilities` 改为按表自动生成、去「已核实」勾选；预检仍校验但真源来自表。触碰适配器层与 preflight，属架构级——按「架构变更立项规范」单独立项，不混入快赢。
- **M33 AI 配置智能化（G4/G5）**：Key → 自动拉模型 → 选中即 Tier A 生成完整实例（能力 + 定价 + 默认建议）；定价未命中表才提示补录。
- **M34 模板与运行入参自动化（G6/G7/G8）**：自然语言 → 模板推荐（Tier B）；inputs 按 brief + 历史 run 预填（Tier A）；RunParams 覆盖项智能默认。
- **M35 创作流程自动化（G9/G10/G11）**：video 参数/模式/画幅由能力表 + 体裁推导；`canvasAdvice` 扩展为全站下一步建议默认开启。
- **M36 运营配置自动化（G12）**：平台预设/合规基础词内置 + 建议补充；排期节奏模板。
- **M37 收尾与回归（G13）**：统一「自动值来源」可追溯 UI（每个预填标注 Tier 与来源），探针全覆盖。

## 六、保留人工的边界（Never / Ask-first）

- **Never（绝不自动化）**：付费执行确认（`strict_delivery`、无自动付费重试）；密钥录入 `secrets.json`（绝不代填/代存明文）；合规放行与法务判断；跨项目引用；密钥进入对话/计划/日志。
- **与「不猜测/不静默降级」冲突处**：以 Tier A「表背书 + 预览闸门」替代「用户手填核实」，而非取消校验。
- **Ask-first**：Tier A「由系统档位表背书替代用户勾选已核实」的采纳（把「填错」风险从用户转移到平台档位表维护上，需用户明确接受）；新增依赖；超加法的 schema 变更；范围扩展。
- **Always**：加法迁移；服务端 → 探针 → 前端；如实记录未通过门禁；收口写验收并校准 roadmap。
