# M57 L1 Spec — 轻松创作「意图驱动的智能载体路由」

> **状态：待用户评审批准；未获批不改业务代码。** 构建在 M30/M40/M56 之上，不推翻其契约。
> 前置复核：编号以最新 roadmap 为准（取 M57）。
> 纪律：**0 新表 0 新列 / 0 新增 action / 0 新增付费面**；路由产出的是**建议 + 预览闸门**（Tier B），绝不自动改出片模板；不破坏 M40"确认什么就做什么"与 `easy-*` 纯执行器本质。

## 一、背景（修正一个长期误解，并把它变成正当诉求）

用户最初的心智模型是"轻松创作应根据对话上下文**智能选模板**"。现状恰恰相反：

- `services/template-recommend.ts` 有一套"自然语言 → embedding 语义匹配 top-K 模板"的能力，但它服务**专业端建项目**，且明确把 `easy-*` 剔除出可推荐集；
- 轻松创作反过来只做 `easy-video`/`easy-dialogue` 二选一，**不去全量模板里挑**。

两套智能被**双向隔离**。用户"想轻松说一句就得到最合适的载体"的诉求本身是对的，只是当前架构刻意没做。M57 把这条能力**以建议形态**接进轻松创作，同时守住"轻量默认、不自动升舱"的红线。

## 二、方案决策（自行拍板，附理由）

| 决策点 | 选择 | 理由 / 已否决替代 |
|---|---|---|
| 路由形态 | **意图分类 → 建议载体（含 easy-* 与专业家族）**，以方案卡"更合适的选择"提示呈现，用户可一键采纳 | 已否决"自动选模板直接跑"——违反确认即执行不变量、且长链路成本失控 |
| 默认归属 | **默认仍落 easy-\*（快速轻量）**；仅当意图明显越出轻内容能力（连载/多角色/长时长/强一致性）才**建议**专业链或 M56 毕业通道 | 保住"零门槛、便宜、快"本质；已否决"把 easy-* 也丢进 top-K 竞价"（会稀释轻松创作的确定性体验） |
| 与 M56 关系 | M57 是**前置路由器**（聊的过程中就给方向建议），M56 是**后置毕业通道**（成片后再升舱）；两者互补不重叠 | 覆盖"事前引导"与"事后补救"两端 |

## 三、路由判定设计（有界、可解释、不猜）

- 新增纯函数 `services/creation-chat/route-hint.ts`：输入 = 当前轮用户文本 + `plan.kind/performance` + 已解析参考摘要 +（复用）`template-recommend` 的向量/关键词匹配产物；输出 = `RouteHint | null`。
- 触发"建议出轻内容"的信号（任一即产建议，附**人话理由**）：
  - 意图含"连载 / 多集 / 第 N 集 / 季 / 续集" → 建议 `series-setup`（→M56 1b）；
  - 意图含"多角色对手戏且要求形象一致 / 定妆 / 逐句配音 / 带 BGM 短剧质感" → 建议 `mengbao-episode`（→M56 1a）；
  - 意图明确"长于 60s 的单条" → 建议专业链（而非 M59 的放宽，见其理由）；
  - 上传视频 + "反推/类似风格成片" → 建议 `video-reverse`（→M58）。
- **不猜**：命中不了上述信号就 `null`，方案卡不打扰；无 vision/解析实例时相关建议不出现（沿用 M31 blocker 不降级）。

## 四、契约与注入

- `planning.ts`：规划 messages 注入一段"载体路由准测"（与 `projectMetaPrompt`/`capsConstraint` 同范式），使 LLM 在 `plan` 同级可产出 `routeHint:{target, reason}`（可选、宽松收下、服务端 `sanitizeRouteHint` 校验 target ∈ 模板真源，非法丢弃不 noise）。
- `contract.ts`：`planningReplySchema` plan 分支加可选 `routeHint`（**不入 planHash**，同 project 先例——路由建议不是执行数据）。
- 服务端 `sanitizeRouteHint`：target 必须是 `listTemplates()` 真实 key 且属于"专业家族白名单"（`series-setup/mengbao-episode/video-reverse/...`），reason 非空 ≤80 字；越界回落 `null`（不静默保留非法建议）。

## 五、前端

- `CreationPlanCard.vue`：方案卡顶部/底部增一条**轻量建议条**（非阻断）："这更像〈连载短剧〉，想要多集连载 + 角色一致性？〔看看怎么升级〕" → 点击展开说明 → 引导至 M56 毕业动作或专业端建项目；无 `routeHint` 完全不渲染。
- 复用既有导航，不新建页面；遵守单文件 ≤800 行红线，必要时拆 `CreationRouteHint.vue` 子组件。

## 六、探针（`scripts/probe-m57.ts`，零网络零计费，隔离库 + stubFetch）

- route-hint 纯函数：连载/多角色一致/长时长/反推四类信号各命中对应 target；无信号返 `null`。
- contract：`routeHint` 可选、缺失向后兼容、错位/非法 target 被 sanitize 丢弃、**不进 planHash**（改建议不作废已确认方案）。
- 注入：无 vision 实例时反推类建议不产出（不降级）。
- 回归：`easy-*` 仍不在 `template-recommend` 可推荐集（M57 不改其排除逻辑）；默认路径（无 routeHint）方案卡渲染零漂移。

## 七、边界与遗留

- 不做自动建专业项目/自动起专业 run（只给建议 + 跳 M56 动作）。
- 不把 `easy-*` 纳入 top-K 竞价（维持双向隔离，仅新增"越界时建议出 easy"这一单向出口）。
- 路由准测信号集是**可扩展枚举**，新信号须同步探针断言，防"指哪打哪"漏收口。
