## 3. 逐项需求卡

### R01：先建立可复现的质量基线

- **现状**：M24 已有小样本图片 A/B 与一致性/风格/质量评分；不等于已经完成多集叙事、视频、声音和成片对照。
- **提升**：保存样本输入、模板/提示词版本、供应商/模型、参数、参考资产版本与实际用量；模型支持 seed 时记录，不支持时明确不可严格重现。
- **评估维度**：角色一致性、跨集矛盾/原作遗漏、镜头可用率、音画字偏差、人工返修次数、每分钟可用成片成本、完成耗时。
- **对照方式**：先比较 ACS 自身开关/策略前后；需要竞品对照时，固定同一原作、可比模型/参数和预算，并记录无法对齐的差异。
- **验收方向**：建议先选一组 3–5 集连续样本、小批预算，形成完整结果和人工抽检记录；小样本只报告描述统计，不声称显著领先。样本、预算和通过阈值在后续开工时确认。
- **边界**：复用 M24 评测；复用 M26 runner 做确定性回归。质量实验不塞进零网络探针，不因登记本需求而立即调用付费模型。

### R02：内容版本、参考版本与影响范围

> **状态（2026-09-18）**：已立项为 **M29** 并**收官交付**——三张通用表（`content_versions`/`exec_snapshots`/`exec_inputs`）+ 不可变文件版本链、文本/实体版本捕获与还原、五类执行消费点真实输入快照与 used/skipped、`downstreamImpact` 只报告不生成、gen 节点 `spec.pin` 锁版与选片/还原三操作分离、前端「历史·影响」面板与锁版控件全部落地。`probe:ci` 25 探针 / 2965 断言全绿（含 probe-m29 46 断言八节）。设计 `2026-09-18-agencys-content-studio-m29-design.md`；review `2026-09-18-agencys-content-studio-m29-review.md`；roadmap §M29 注记。**本卡保留为需求溯源留痕**。以下为原始立项前勘察。

- **现状**：run 有模板/参数快照、镜头有多版本；M25 章节/事件内容编辑采用同路径覆写和修改计数，未保存可回看的原文历史。不能把现有快照理解成所有输入内容都已冻结。
- **提升**：对章节、事件、设定、参考图、台词、镜头和合成结果建立可追溯版本关系；一次生成能定位实际消费的内容/参考版本，而不只记录可变资产 ID。
- **用户流程**：修改后先显示受影响的集/镜头/成片及更新原因，标记“上游已变更”；用户选择范围并确认预计成本后再更新。
- **历史保护**：已确认镜头可锁定旧参考版本；保留旧成片与选片结果；还原版本是切换选择/产生新版本，不静默覆盖全部历史产物。
- **验收方向**：修改一个角色参考图或一章事件，仅命中真正依赖项；未引用资产的镜头不进入更新计划；旧 run 仍可展示当时输入；重复确认与恢复不导致重复生成计费。
- **边界**：不默认全局重渲染；缺少历史正文的旧资产明确显示“历史不可恢复”，不伪造版本。持久化模型及迁移方案留给 L1 论证，复用通用领域模型。

### R03：叙事连续性与可追溯长篇上下文

- **现状**：已有事件图谱、摘要、角色 states 与剧本对原作审计；本轮未发现足以证明“长期状态演化与跨集冲突都已闭环”的证据。
- **提升**：区分不变设定与随时间变化的状态：人物关系、已知信息、伤势、服装、道具归属、地点/时间、已发生事件、未兑现伏笔；显式标注状态适用的集/镜头及来源。
- **长文策略**：按章节/事件分块提取和检索，保留原文来源；摘要只作导航，关键事实回查原文。超出输入预算需分段或告警，不能把截断后结果称为完整理解。
- **增量策略**：追加章节或修订原作后先识别变化和受影响分集，再通过 M27 的已验收能力受控推进；不重做 M25 的增量导入端点。
- **验收方向**：构造跨集冲突样本（道具已转交却再次持有、角色提前知道秘密、服装/伤势状态错误等），输出可点击的来源与冲突位置；人工允许的改编偏离可登记，不反复误报。
- **边界**：不引入重型图数据库作为先决条件，不承诺无限上下文与零遗漏；事实修订优先于旧摘要，具体冲突裁决规则在 L1 确认。

### R04：视觉一致性从“能传参考图”提升为“可控参考策略”

- **现状**：角色/场景/道具参考注入、states 出图、风格预设已在位；效果仍受模型、参考质量、多角色构图和供应商能力影响。
- **提升**：角色基准参考与状态变体分层选择，多视角参考、服装/道具状态、统一风格与负向约束成组复用；记录每镜实际使用的参考及模型能力。
- **兼容语义**：不支持参考图数量、首尾帧或特定参数的模型明确提示；关键一致性约束无法执行时由用户选择替代方案，不能静默降级后仍显示“已锁定”。
- **质量反馈**：复用 R01/M24，逐角色评价跨镜、跨集差异；扩展视频抽帧检查，标注抽样覆盖范围，保留人工复核。
- **验收方向**：同角色跨集/多视角/不同状态，以及双角色同框样本对照；既量测收益，也记录串脸、状态误用与风格漂移失败样本。
- **边界**：FaceID/IP-Adapter/LoRA 等只作后续可选技术验证，需供应商/算力/授权条件成立再立项；不把文本向量库称为人脸身份库，也不承诺不变脸。

### R05：统一多阶段质量检查与问题定位

- **现状**：剧本审阅、分镜可剪辑性检查、M24 图片评分/文本合规、M25 原作审计已有，但粒度、报告结构与后续操作不同。
- **提升**：统一问题记录语义：检查维度、严重度、证据、目标集/镜头/台词/资产版本、建议处理、人工裁决；能从报告定位到当前工作台对象。
- **检查层次**：剧本因果/覆盖 → 分镜台词/动作/状态 → 生成图/视频的角色与场景 → 成片音画字、黑帧/静音/缺镜等技术质量。
- **门禁策略**：沿用显式 action 与人工 gate；旧模板默认行为不变。新质量模式中必需检查失败/不可用应显示“待人工验收”，不能将无结果当作通过。
- **验收方向**：故意注入漏台词、缺镜、状态矛盾、音频过长等问题，验证定位及严重度；检查服务不可用/输出格式异常时，有明确未知状态和人工出口。
- **边界**：LLM 评分不是唯一真值；确定性检查与主观评价分开。视觉内容合规如需扩大范围另行明确，不作法律或版权鉴定承诺。

### R06：受控、有限次数的定向返修

- **现状**：ACS 已能单镜重生成、多版本选片和重新合成；本轮对比没有证明 ACS 或 Toonflow 已完成可放心无人值守的质量返修闭环。
- **提升流程**：问题报告 → 修复建议及 diff → 影响范围/成本预估 → 用户批准 → 定向生成新版本 → 重新检查 → 用户采纳或保留原版。
- **自动化边界**：默认人工确认；未来可对明确授权的问题类型、目标范围和预算开放有限自动执行。原作改写、人物设定变动、发布等不能由质量评分隐式授权。
- **停止条件**：重试次数/累计费用/时长到限、质量无改善、供应商不支持、输入版本变更或人工取消时暂停；不能为追求达标无限生成。
- **验收方向**：只返修失败镜头，已通过且锁定镜头不重复计费；拒绝新版本后旧选片仍有效；中断恢复/重复点击不重复提交；两轮无改善能停并解释原因。
- **边界**：复用 M27 与既有任务/镜头机制，不另建平行调度引擎；“回滚”指恢复版本选择，不代表撤销已经发生的外部模型费用。

### R07：叠加对话式专业协作层

- **现状**：ACS 的专业方法由模板、提示词和 action 承载；Toonflow 的明确分工与对话调度更容易让用户感知谁在处理哪一步。M23 画布 AI 当前只给建议，执行编排留给 M27。
- **提升**：在 M27 上层提供自然语言目标与任务澄清、创作方案草案、编剧/导演/审阅等可配置职责、执行进度和结果解释；角色可以是逻辑工作单元，不要求全部独立进程/模型。
- **执行要求**：自然语言先转为结构化可检查计划，展示模板/动作、输入引用、范围、成本和 gate；批准后只调用已登记且已验收的工具。
- **经验沉淀**：经用户采纳的修改可沉淀为项目规则或摘要，记录来源和适用范围，不让一次主观审阅污染全局设定。
- **验收方向**：如“仅调整第 3 集第 5 镜的服装，其他不动”，能展示正确范围和计划；模糊指令先澄清；拒绝计划不产生生成任务；过程可回溯到既有 run/step/task。
- **边界**：不为模仿多 Agent 数量重写 DAG，不新增体裁专属表；先接确定性能力，再开放经批准的返修。M27 若已实现其中部分，按实际交付删减重复项。

### R08：视频片段的音画字精细联动

- **现状**：流水线 ffmpeg_merge 的逐镜音字对齐当前限静态图路径，clips 路径记录 motion_mode 回退；画布 M22 已有分段对齐，但对齐与转场叠加、模糊段匹配仍有边界。不能笼统写成“没有字幕对齐”。
- **提升**：视频片段、台词、配音、字幕共用清晰时间基准；提供逐句停顿/语速与镜头时长预览，处理片段裁切、延长、转场叠加及 BGM/SFX 混音的时间偏移。
- **交互目标**：修改一句台词或一段配音后展示受影响字幕/镜头/成片，只重跑必需部分；能试听、对照字幕并做小范围微调。
- **进阶能力**：复用 M25 ASR 做时序辅助；词级强制对齐、说话人分离、口型同步分别评估。普通转写和逐句测时不等于这三者已实现。
- **验收方向**：静态与 clips、多角色台词、长短句、静音镜头、转场、不同帧率样本；检查无截断对白、字幕不越界、总时长与逐句偏差可测，允许阈值由样片基线确定。
- **边界**：不承诺专业 NLE 全功能；优先补现有生成/合成链的精细控制，保留旧路径行为和明确降级提示。

### R09：工作台衔接与剩余画布保真

- **现状**：画布、流水线、镜头工作台都已存在；M22 明确排除了部分 last_frame/source 编辑边及 LLM reference 模板映射，不应仅凭 v3 名称认定所有路径无损。
- **提升**：质量报告、实体版本、分镜、生成节点之间按同一业务对象定位；在不同视图切换时保留选择与来源信息，减少复制 prompt 和重复绑定素材。
- **转换目标**：画布 → 模板 → 运行对支持的端口保真；不支持项逐项提示并给出处理路径，不能静默丢边后宣称等价。结合 M27 子模板实际契约复核 remaining lossy 项。
- **版本联动**：双向操作消费 R02 的版本与影响模型，避免同一镜头在两处编辑互相覆盖；生成历史与当前采用版本清晰区分。
- **验收方向**：同一镜头在三个入口往返可定位；首尾帧/参考/编辑边逐类测试支持或明确拒绝；模板试跑与画布直接运行的输入引用可对照。
- **边界**：不重做无限画布、不重新加入 M23 已交付的虚拟化/布局；跨项目复制、run 节点及历史迁移仍按既有隔离策略，扩大范围需后续 spec 论证。

## 4. 建议开发顺序与启动条件

### 启动门槛

1. **M27 完成开发并收官**：以其最终 spec、验收记录和实际代码为准，不以“已排期”替代“已完成”。
2. 重新对照 M19–M27/M28 实际交付逐项销账，尤其 R07/R09 与 M27 的重合部分；当前文档不预先断言 M27 最终不包含某项能力。
3. 保留全部 R01–R09 的去向：已交付、待立项、合并或明确排除均留痕，优先级靠后不等于取消。
4. 每次仅启动一个 L1：需求勘察 → 用户拍板 → 分配可用编号/编写 spec → 实施 → 探针/实测 → 验收复盘 → roadmap 校准。
5. 架构级变更单独论证；延续通用表、单机 Web、自研状态机、≤800 行治理等既有约束。本次登记不授权提前改动这些基线。

### 建议分组（不是已批准的新里程碑）

| 顺序 | 主题 | 对应需求 | 退出依据 |
|---|---|---|---|
| 第一组 | 测量与可追溯基础 | R01 + R02 | 有质量/成本基线，能追溯版本和受影响对象 |
| 第二组 | 连载与成片品质 | R03 + R04 + R08 | 跨集设定/视觉/音画字改善可由同基线验证；开工时按规模拆批 |
| 第三组 | 质量与有限返修 | R05 + R06 | 问题定位、批准、定向修复、复检、停止及恢复链可验收 |
| 第四组 | 统一创作协作体验 | R07 + R09 | 对话与多视图共用已验证执行面，操作及版本含义一致 |

R01 的评测随各组重复执行，不是只做一次。未完成下层可靠性验证前，不开放上层无限自治执行。此处不安排日期或工期，避免基于未完成的 M27 设计提前承诺。

## 5. 明确不纳入与效果声明

- 不把“没有独立导演 Agent”“没有人脸向量库”本身当作产品缺陷；先看任务效果、成本与操作负担。

- 不重复立项 M19–M27 已覆盖的基础配音字幕、事件图谱、参考图、画布、审计、预算和跨模板串链。
- 不在本轮执行生成实验、启动服务、修改应用源码、提交代码或创建远程 Issue/Milestone。
