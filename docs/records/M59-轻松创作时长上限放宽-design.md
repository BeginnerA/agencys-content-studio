# M59 L1 Spec — 轻松创作单条时长/镜头上限「有节制放宽」

> **状态：待用户评审批准；未获批不改业务代码。** 构建在 M30/M32 能力背书档位之上。
> 前置复核：编号以最新 roadmap 为准（取 M59）。
> 纪律：**必须一次收口全部写死点**（这是"指哪打哪"高发陷阱）；单镜时长上限不动（受视频模型 caps 档位硬约束，放开无效）；定位是"稍长的单条"，**真正长内容/连载归 M56 毕业通道，不靠膨胀 easy-\* 上限**。
> 优先级：**P2**（收益有限、有截断/回归风险，排最后，幅度保守）。

## 一、背景与"为什么保守"

现状上限（已核实到行，四处写死且必须同步）：
- `contract.ts` L30 `duration: min(30).max(60)`；L45 `shots: .min(2).max(12)`；L40 单镜 `duration: min(1).max(15)`；L37 `lines: .min(1).max(36)`。
- `clamp.ts` L116 总时长重算钳 `Math.max(30, Math.min(60, round(sum)))`。
- `buildCapsConstraintMessage`（planning 注入 LLM 的"30–60 / 建议段数"准测）。
- `workspace/prompts/creation-plan.md` 范围段。

用户诉求：偶尔想要"比 60s 稍长一点的单条"。**但**——把 easy 上限放开与"轻松创作=快速/轻量/便宜"的本质相悖，长内容本该走 M56。故 M59 只做**有节制**放宽，且明确不是主线。

## 二、方案决策（自行拍板，附理由）

| 决策点 | 选择 | 理由 / 已否决替代 |
|---|---|---|
| 目标总时长 | **60 → 90s**（保守 +50%） | 已否决"放到 120s+"：plan JSON 体积与 LLM 截断风险陡增，且与"轻量"本质冲突；>90s 一律走 M56 |
| 镜头上限 | **12 → 16 镜** | 90s 若按 ~6s/镜约 15 镜，16 留余量；单镜 1–15s **不动**（caps 档位硬约束） |
| 台词上限 | **36 → 48** | 与镜头/时长同比，避免"能放更长却台词打不住"的自相矛盾 |
| plan 截断上限 | **65000 字符 → 评估同步放宽**（见 §3.4） | 90s≈16 镜 plan 体积↑，可能撞 `parsePlanningReply` 截断，必须连带评估，否则 schema 放行却被截断判 invalid |

## 三、收口清单（一处不落，逐条改 + 逐条断言）

### 3.1 契约层 `contract.ts`
- L30 `duration` max 60→90；L45 `shots` max 12→16；L37 `lines` max 36→48；L40 单镜 max **保持 15**。
- superRefine"镜头时长和 = duration"一致性校验随新范围仍成立（无需改逻辑，仅确认边界值用例）。

### 3.2 钳制层 `clamp.ts`
- L116 `Math.min(60, ...)` → `Math.min(90, ...)`（与契约 max 同步；不同步会出现"schema 放行 90 却被钳回 60"的自相矛盾——本项最大风险点）。

### 3.3 注入层 `buildCapsConstraintMessage` + `creation-plan.md`
- 告诉 LLM 的范围从"30–60"改"30–90"、建议段数上调；与 caps 档位实际支持取交集（模型 caps 只到 60 时，注入仍以 min(90, caps 支持) 为准，不谎报能力）。

### 3.4 截断层 `parsePlanningReply`（contract.ts 后段）
- 复核 65000 字符上限对"90s/16 镜"典型 plan 是否够用；不够则同批放宽（并计入成本预估），够则显式断言"未放宽"，避免遗漏埋雷。

## 四、计费与能力背书

- 费用随镜头/时长线性上升：`estimate` 口径不变（已按 shots/时长计），budget 检查自动覆盖；确认卡如实显示更高预估。
- 能力背书档位：超 60s 依赖视频模型实际 caps；未登记/不支持的模型走既有 fail-closed，不因放宽而静默降级或强出。

## 五、前端

- `CreationPlanCard.vue` 时长/镜头展示随新上限放开（无硬编码 60 的地方需一并检索替换，禁"指哪打哪"）；方案编辑控件范围同步。

## 六、探针（`scripts/probe-m59.ts` + 存量回归）

- 新边界：duration=90 / shots=16 / lines=48 合法；91 / 17 / 49 拒绝；单镜=16s 仍拒绝（上限未动）。
- 一致性：sum(shots)==duration 校验在新范围成立；clamp 不再把 90 钳回 60（回归最大风险点专项断言）。
- 截断：典型 90s/16 镜 plan 在 `parsePlanningReply` 不触发截断 invalid（或按 §3.4 放宽后通过）。
- 存量收口回归：检索并同步**所有**硬编码 30/60/12/36 的探针断言与 `docs/templates.md`；旧 M30/M41/M45 plan（≤60s）零回归向后兼容。

## 七、边界与遗留

- 不做"超长单条"（>90s 归 M56 专业链）；不动单镜 caps 档位上限。
- 放宽是**可回退参数**（集中在少数常量，若上线后截断/成本问题显著可回调 60）。
